# 第二台电脑与实际部署验收

当前候选：0.2.0-candidate.5。使用该版安装器及同版哈希清单；具体测试结果与未完成项见交付报告。

本说明是待执行步骤，不是双机通过证明。单机测试创建独立客户端目录、身份和端口，仅证明协议链路。

## 本人两台电脑（无需企业源码）

1. 从个人候选取得源码，在没有私有 npm 配置的目录执行 `npm ci`、`npm run build`、`npm test`。如只用本机功能，不安装 PostgreSQL、不设置中心地址，核验历史、任务、额度、用量、备注/收藏、备份恢复、诊断均可使用。
2. 在本人管理的服务器部署 `packages/sync-service` 与专用 PostgreSQL 数据库。提供可信 TLS 证书、独立数据库密码和至少32字符的随机 `SYNC_OWNER_TOKEN`。远端地址使用 HTTPS；不关闭证书验证。电脑只需出站连接服务器4321端口，无需开放电脑入站。
3. 第一台电脑打开「个人多设备」→「连接自建服务或恢复账号」，填写服务地址和初始产品恢复码，连接本人账号。立即在「我的设备」更新产品恢复码并保管，后续不把管理员/初始凭据发给他人。
4. 在第一台生成本人设备配对链接，在第二台粘贴链接，核对服务和本人空间后确认。设备应同属本人、具有两个独立凭据，配对链接只能消费一次。不要复制产品数据库/第一台设备凭据。
5. 初始没有授权：可见心跳，但中心无任务/额度事件。分别选择账号额度和项目用量、时间范围/保留期、项目共享别名后确认。未知额度账号先在「账号与来源」明确绑定，不能假称自动确认。
6. 在自己的 Codex 中开展一段明确的任务。等待至少两次后台额度查询，查看同步时间推进；重启 Monitor 后应继续。另一台个人同步页能看到授权元数据；不应出现对话正文、代码或完整路径。
7. 第一台断网继续产生记录，恢复网络后等待补传，核对事件/用量不重复。两台读取同一日志副本时仅能在稳定事件身份相同的情况下去重，不能用数值相同猜测重复。
8. 暂停授权后本机不再排队发送；恢复后仅按仍有效范围补传。断网撤回应显示待中心确认，联网确认后该授权数据不可查询；有另一份有效重叠授权的记录仍保留。下载到外部的旧导出无法召回。
9. 独立撤销第二台设备，其旧凭据不再可用，第一台继续。恢复码轮换后旧恢复码不可登录，现有设备凭据生命周期独立。退出托盘后核对本产品进程及本地4318端口均关闭。

## 公司（需要私有企业服务）

1. 按私有 Hub README 部署 PostgreSQL、HTTPS 和 `/admin/`，创建公司。管理员创建两个单次邀请，分别给两位员工。员工在本机 Codex 自行登录，Monitor 不索取 AI 密码、API Key 或 Cookie。
2. 先验证首次邀请提交后丢响应：恢复网络、重启 Monitor，使用待完成项继续确认加入，后台仍为同一成员。不要把邀请交给另一电脑来恢复身份。登记已被撤销或轮换时，通过“恢复身份并重新登记”提供本人有效恢复码并明确确认；普通断网仍继续原登记。

   两位员工无需现有产品恢复码，即可在「公司连接」预览真实公司名/地址，输入姓名接受自己的邀请。后台应显示两名成员，各一台设备；为第一名员工再配一台电脑后仍是两名成员、三台设备。
3. 员工逐项授权自己的账号/项目/时间。管理员看日、周、月、自定义时区报表，按员工/账号/项目/模型过滤；导出结果与同范围屏幕统计一致。跨日迟到事件与更正回到原发生阶段，额度快照不与阶段用量混算。
4. 撤回、到期、停用成员后重新查询看板/明细/导出；设备不得再上传或管理成员。普通成员仅能读取本人数据；查看角色没有导出/管理权限。记录测试账户/设备数量和网络出口数量，不记录真实凭据/对话。
5. 分别测试无任务时仍在线、采集源读取失败、网络断开、服务器重启和证书错误。连接、采集器、AI任务状态应分别变化。

## 安装、Hooks、通知和回退

真实 Windows 安装/升级/卸载仍须记录所用版本、安装目录、快捷方式及卸载登记。默认卸载保留 Monitor 数据，不删除 Codex 文件。不要用杀进程替代托盘退出。开启 Hooks 前审核准确配置并通过 Codex 自身信任流程；发起新主/子任务、等待、完成/中断后验证真实回调。通知需实际系统权限和一次真实触发。

升级前用 SQLite backup API 或产品备份导出一致性快照；不要仅复制活跃主数据库忽略 WAL。故障回退使用匹配的旧程序和升级前快照，先保存新数据与撤回/删除状态。发生撤回后优先使用产品恢复流程，恢复会清除旧连接并保留删除语义，再重新配对授权，不直接覆盖复活旧权限。中心用 `pg_dump -Fc` 备份，恢复到新库验证后切换连接地址。
