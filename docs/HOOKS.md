# 增强实时状态：一个可选开关

默认关闭，不影响历史、用量、额度与已有 Agent 记录。

## 使用

1. 设置与诊断 → **增强实时状态** → 开启。
2. 首次按 Codex 提示审核并信任 **AI Work Monitor · 本机状态观察**。CLI 可使用 `/hooks`；当前桌面 alpha 的具体入口和事件覆盖仍待现场验证。无需复制配置、找脚本或手动合并文件。
3. 收到真实状态事件后，界面显示“已收到状态事件”。此前显示“等待 Codex 确认或新的状态事件”，不假装已生效。

日常关闭只需关闭同一个开关。程序立即停止接收，禁用本机回调写入，并自动移除自己安装的准确条目；其他 Hook 保留。Codex 仍缓存旧条目时，它们也不会继续记录。若条目被手动修改或文件不可写，程序停止接收并提示清理未完成，不覆盖用户改动。

## 自动处理与边界

开启仅修改当前 CODEX_HOME（默认 ~/.codex）下的 hooks.json；先保存原文件备份到本产品数据目录 hook-backups，再合并本产品条目。不修改 config.toml、信任数据库或公司管理策略。重复开启不重复添加。新条目或定义发生变化时，Codex 可能再次要求信任。

“查看详情与配置”可以审核生成的完整定义。脚本只保留事件名、会话/回合/Agent ID、观察时间，最小工具调用关联ID，以及是否调用等待用户输入工具的布尔值，不联网、不保存提示词、工具名或工具输入输出、不改变审批决定；上限1 MiB输入，1.2秒内部超时，无stdout。关闭时 hook-enabled.json 门控立即生效。程序自身的 hook-install.json 记录精确所有权；恢复/迁移后缺少该记录时不盲删外部条目。

不使用绕过信任的参数；安装配置、用户信任、收到事件、具体事件覆盖是不同状态。没有等待证据仍显示未知，Stop 本身不证明成功。

## 0.1.2 的状态边界

- 同一回合已确认完成、失败或取消后，低可信度回调不能改回运行。新回合启动仍可继续同一会话。
- `SubagentStart` / `SubagentStop` 中的 `session_id` 是父会话，`agent_id` 才是子 Agent；回调仅关联已索引、身份无歧义的子会话。父回合 ID 保留作来源信息，不写成子会话的回合。已知父关系冲突时暂存等待检查。
- 回调早于索引时进入 Monitor 数据库的持久待处理队列；后续扫描重试，重启不丢失，重复投递不会重复入库。已删除会话的回调不使其复活。用户主动导出的支持文件可检查等待索引和拒收情况。
- Hooks 公共字段没有可依赖的上游发生时间。因此保存回调观察时间、Monitor 首次收到时间，并显式标记 `hook_callback_observed`；历史重放不会把“最后观察时间”改成重放时刻。
- `PermissionRequest`、等待用户输入工具的 `PreToolUse`、`PostToolUse` 属于推断证据。它们可能受到其他 Hook 影响；等待审批不等于已经显示审批窗口。`Stop` / `SubagentStop` 可以触发继续执行，不能当作成功完成。`Interrupt` 对实际中断回合提供确认取消证据。
- 失败只在收到明确的终态证据时显示；普通上游错误记录只是诊断，不能推断整项任务失败。源日志静默或状态证据过期显示未知，不推断完成。

  0.1.2 新增 `PreToolUse` 以观察等待输入工具。升级不自动重装已经开启的旧配置，不改用户当前选择；配置预览会返回 `updateAvailable` 和 `missingEvents`。若希望补全覆盖，在详情审核后关闭再开启，并完成 Codex 要求的重新信任。尚未完成时，旧配置已有事件仍可接收，等待输入覆盖仍待验证。

目标电脑须分别验收首次信任、真实等待输入、真实审批及当前客户端的子Agent回调，合成测试不能替代。PostToolUse只在可靠tool_use_id关联时解除对应等待；无关或缺关联回调仅观察活动，不能清除等待。PermissionRequest没有已验证的调用关联字段，不能按工具名或时间猜测已结束。

依据：[OpenAI Docs：Hooks](https://learn.chatgpt.com/docs/hooks)。非托管 Hook 的首次审核信任由 Codex 要求，产品不能代替。
