# 补回旧监控历史

适用版本：0.2.0-candidate.4（沿用 candidate.3 补回入口）。此功能用于在当前监控库中补回另一个完整备份独有的历史，保留当前新增记录、设备身份、设置、备注、置顶、账号时间绑定和同步状态。Codex 源日志及数据库始终只读。

## 使用

1. 从 Windows 开始菜单、桌面快捷方式或文件资源管理器打开已安装的 Monitor。不要从已识别的隔离工具环境启动桌面版；该环境可能看到不同的数据视图。程序会拒绝这类已知入口并提示正确打开方式，不自动选择或覆盖另一份数据库。
2. 将已完成的 SQLite 一致性备份副本放到本产品数据目录的 `backups` 中，使用 `monitor-数字.sqlite` 文件名。不要直接复制仍在写入的主库文件；主库可能还有未检查点的 WAL 数据。
3. 打开「设置 → 高级设置与故障排查 → 补回旧监控历史」，选择旧备份并预览。预览运行完整的隔离演练，不更改当前记录。
4. 核对预览条数后确认补回。程序短暂停止采集、同步和额度刷新，等待在途写入结束，再为最新库创建一致性备份。预览之后新收到的记录也在备份与合并范围中。
5. 成功后会显示实际补回条数和修复前备份文件名。采集自动恢复；再次用同一旧备份执行不会增加重复事件或重复归档。

预览绑定旧备份的 SHA-256，十分钟后过期；更换或修改备份必须重新预览。当前或旧库存在共享/配对/撤销状态、非空同步队列或冲突的账号/来源/绑定时，此定向恢复会拒绝操作，不猜测身份、不扩大授权。需保留证据另行迁移。

## 账号与来源冲突

同来源账号关联按半开时间区间比较，不能仅按绑定 ID 合并。相邻区间允许；不同账号重叠、同 ID 内容冲突、旧有效关联覆盖当前撤销区间都会停止补回。同账号重叠仍须验证当前任务账号、原有 Token 按账号统计和额度观察归属不变。遇到冲突保留两份备份，通过账号与设备核对或联系支持，不自动猜测身份。

同一来源仅扫描时间、健康状态或显示名称变化时保留当前观察，旧观察另存本机。稳定来源身份或已知路径配置不同仍拒绝。页面给出中文处理方法；导出的支持文件含安全错误码，不包含原始异常路径或凭据。

## 保留与提交边界

- 按稳定事件 ID 补入缺失原始事件；同 ID 的不同原始载荷完整保存在本地 `history_recovery_evidence` 中，当前活跃记录优先。这些证据归档不再次计入用量。
- 只对能够证明来自同一会话、同一元信息内容的数据库元信息记录消重；不能凭相同用量数值认定重复。
- 额度观察保留原账号和来源；展示历史不代表账号身份合并。同账号不同设备的百分比不相加。
- 永久删除标记取并集并优先生效，不恢复已删除会话或旧共享授权。
- 沿用生产用量与状态投影。只有会话头、没有用量证据的记录显示未知；实际记录为零的用量仍显示 0。
- 输入备份的哈希保持不变。提交前核对当前库的全部表与结构仍等于冻结备份；意外并发写入会拒绝提交。SQLite 单事务应用，写入或校验失败整体回滚；不替换活动数据库连接、不生成新的设备身份、不重加密原凭据。

## 备份与恢复

执行前一致性备份位于本机数据目录 `backups/monitor-时间戳.sqlite`。本次运行的预览、隔离合并结果和 Monitor 自身配置副本位于 `history-recovery/运行ID/`。这些文件包含私人记录，只留本机；不要上传或带到另一台电脑。

事务失败无需手工覆盖数据库，原库保持原状。需要撤回一次成功修复时，先保留修复后的新备份，再从产品恢复入口选择执行前备份。该入口会明确清除远端配对；已有新的删除或撤回状态时必须走产品恢复入口，不能用文件复制复活旧授权。保留原凭据文件，禁止复制其他设备的数据库或 DPAPI 文件。

## 离线演练

仅接受已完成的静态备份；拒绝非空 WAL/回滚日志。以下命令只创建新输出目录，不替换原库，也不启动采集或联网：

```powershell
npm run repair:history -- --current current-backup.sqlite --legacy old-backup.sqlite
npm run repair:history -- --current current-backup.sqlite --legacy old-backup.sqlite --output new-recovery-directory
```

第一条只预览；第二条生成新 `monitor.sqlite` 和条数/哈希报告。线上应用应使用产品入口，确保最新数据已冻结和备份，不把离线结果直接覆盖仍在采集的数据库。
